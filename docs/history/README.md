# 实施记录（history）

> 本目录收录**一次性**的功能实施记录：每个功能一篇 `NN-<slug>-spec.md`，记录「需求 → 设计 → 实施」全过程与状态。
> 与 [../design/](../design/README.md)（长期规范）相对——规范讲「怎么建」，实施记录讲「当时怎么做的、为什么」。
>
> ⚠️ **模板裁剪提示**：以下记录写于模板化之前或跨产品线沿用。部分能力（AI 运行时、会话/消息、终端、
> 文件树、MCP、记忆引擎、IM 渠道、编辑器等）已随模板化剥离，相关段落里的代码路径可能不存在。
> 已剥离清单见根 [AGENTS.md](../../AGENTS.md) 末节；现行架构见 [../design/template-architecture.md](../design/template-architecture.md)。
> 版本号、平台数量、必需检查数等也是**当时状态**（例如旧版三平台 / 5 项检查），不代表当前仓库。
> 每篇的「与当前模板的关系」一列说明了哪些部分仍然有效。

1. 新功能按 32 号流程产出 `NN-<slug>-spec.md` 落本目录，**编号从 40 续号**（既有编号保留，不复用），并在上方索引表登记。
2. 实施记录写完后**冻结**：后续语义演进时更新对应的设计规范（`../design/`），不在实施记录里追加；实施记录只补「实施状态」一栏。
3. 彻底过时的实施记录直接删除（git 历史可追回），不设归档目录；仍有参考价值的平台踩坑在删除前固化到代码注释或对应规范。
